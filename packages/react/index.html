Named components

Section titled “Named components”

Each sign is available as a PascalCase named export derived from its code and name.

The component name pattern is {Code}{Name} — e.g. P001NoSmoking, W001Flammable, F001FireExtinguisher, M001WearEyeProtection.

SignById component

Section titled “SignById component”

Use SignById when the sign is determined at runtime.

Props

Section titled “Props”

Named component props

Section titled “Named component props”
Prop Type Required Description
width number No Width in pixels. Defaults to the SVG’s intrinsic width.
height number No Height in pixels. Defaults to the SVG’s intrinsic height.
title string No Sets the SVG <title> element for screen readers.
description string No Sets the SVG <desc> element for additional context.

SignById additional prop

Section titled “SignById additional prop”
Prop Type Required Description
id string Yes Sign ID, e.g. "e001-emergency-exit-left-hand".

All named component props also apply to SignById.

Accessibility

Section titled “Accessibility”

Every component renders an <svg> with role="img" and an aria-labelledby attribute pointing to the generated <title> and <desc> elements, which default to the sign name. Passing aria-label labels the <svg> directly instead. Ids are unique per instance, so the same sign can appear any number of times on a page.

Decorative signs that are already labelled by surrounding text should omit title and add aria-hidden="true".
